# 低空交通监测系统

面向城市低空交通监管的**纯前端演示系统**。围绕「无人机低空飞行管理 → 航线规划 → 任务执行 → 数据管理」
这条业务链，叠加交通状态识别、异常事件检测、交通违法取证三类 AI 分析能力，
核心交互是**按告警事件筛选正在执行该事件的无人机，并查看它的航线、任务数据与数据资产**。

> 纯前端演示：无后端、无数据库、无真实接口。所有数据来自本地 mock，地图底图使用高德公开栅格瓦片。

---

## 快速开始

### 方式一：一键启动（Windows）

双击项目根目录的 **`start.bat`**。脚本会自动完成：检查 Node.js 环境 → 首次运行时安装依赖
→ 检查 5174 端口占用（被占用时可选择结束残留进程）→ 启动开发服务器并打开浏览器。
全程无需手动输入命令，`Ctrl+C` 停止服务。

### 方式二：命令行

```bash
npm install
npm run dev
```

打开 `http://localhost:5174`（hash 路由，默认进入 `#/monitor`）。

| 命令 | 作用 |
| --- | --- |
| `start.bat` | 一键启动（Windows，双击运行） |
| `npm run dev` | 开发服务器，端口 5174 |
| `npm run build` | 生产构建，产物在 `dist/` |
| `npm run preview` | 预览构建产物 |
| `npm run check:data` | mock 数据外键一致性自检（**改数据后必跑**） |

## 页面

顶栏 7 个导航：监测总览 → 空域管理 → 航线规划 → 任务执行 → 数据管理 → 取证存证 → 统计分析。

### 监测总览 `#/monitor`

三栏布局，与设计稿逐项对应：

- **左栏**
  - 低空运行概览：无人机集群 / 空域范围 / 时间范围 三个筛选 + 4 项运行指标（在线无人机、飞行架次、总航时长、覆盖里程）
  - 无人机低空飞行管理：**航线规划 / 任务执行 / 数据管理** 三个 Tab，配任务类型、执行状态、所属机队筛选与关键词搜索
  - 告警事件 / 任务记录：5 条事件，**点击即筛选**
- **中栏** 地图：图例（无人机位置 / 航线轨迹 / 任务区域 / 交通航区，可逐层开关）、实时任务开关、指北针、缩放与比例尺
- **右栏**
  - 事件详情：事件类型 / 位置 / 关联无人机 / 时间 + 航拍快照 + 取证状态 + 「查看飞行航线」
  - AI 识别分析：三类能力 Tab + 拥堵等级 / 异常事件 / 违法取证 / 运行识别四项指标 + 事件置信度圆环 + 最新识别结果

### 空域管理 `#/airspace`

OA 表格（12 列）+ 右侧范围预览地图。管理禁飞区 / 限飞区 / 电子围栏 / 航路走廊：

- 新建空域：选中心点（真实路口）+ 半径 + 边数，自动生成多边形；航路走廊按长条形生成
- 编辑 / 删除带二次确认，多边形随中心点与半径重算
- 按类型 / 管控等级 / 所属区 / 状态 / 关键词筛选
- 写操作受角色权限控制（只读访客看不到写按钮）
- 监测总览地图同步多一个「空域围栏」图层开关

### 航线规划 `#/routes`

OA 表格（12 列）+ 右侧轨迹预览地图。**支持写操作**：

- 新建航线：从上海 70+ 个真实路口里选起点 / 途经点 / 终点，
  系统用 Catmull-Rom 样条插值成平滑轨迹，里程与时长自动测算（按巡航 18 km/h）
- 编辑航线：改锚点后轨迹、里程、避障绕行段自动重算
- 删除航线：二次确认；**被任务占用的航线禁止删除**，避免任务指向不存在的航线
- **避障与返航**：可配避障策略、安全间距、安全高度区间、返航点 / 模式 / 触发电量 / 返航高度；
  在监测总览聚焦某条航线时会画出橙色绕行段与返航点标记
- **与任务双向关联**：「绑定任务」列可点击，跳到任务执行页并自动打开该任务详情
- 按所属区 / 绑定状态 / 关键词筛选，选中任意行即时预览轨迹

### 任务执行 `#/tasks`

OA 表格（13 列）。六个筛选维度（类型 / 执行状态 / 审批状态 / 机队 / 区 / 关键词）。

- 点任意行打开详情弹窗：飞行参数、执行航线、覆盖任务区域、采集数据资产清单
- **与航线双向关联**：表格「执行航线」列显示 `编号 + 名称` 且可点击，
  跳到航线规划页并选中该航线；详情弹窗里有独立的「执行航线」区块
  （起止点 / 里程时长 / 锚点轨迹点数 / 避障策略 / 返航点 / 返航模式）
- **任务审批**：详情弹窗内含审批记录时间线，支持提交 / 通过 / 驳回 / 撤回四态流转；
  通过或驳回必须填审批意见；操作按钮按角色权限显隐
- 审批状态与执行状态**相互独立**——审批通过不等于已派发

### 数据管理 `#/data`

OA 表格（11 列）+ 四张类别汇总卡，按角色密级过滤可见数据。

- **回传**：回传状态（已回传 / 回传中 / 排队中 / 失败）、进度条、链路质量、带宽、重试次数
- **存储**：存储分层（热 / 温 / 冷 / 取证存储池）、保留天数、到期时间
- **检索**：类别 / 存储位置 / 关联任务 / 回传状态 / 存储分层 / 访问密级 / 关键词 七个维度
- **导出**：整表或单条导出 CSV（含 UTF-8 BOM，Excel 打开不乱码；含逗号字段自动转义）
- **权限**：四种角色切换（系统管理员 / 监管主管 / 业务操作员 / 只读访客），
  按密级过滤可见数据，导出按钮随权限启用或禁用

### 取证存证 `#/evidence`

哈希链可视化 + 一键校验：

- 每条取证记录是一「环」，带区块高度、本条哈希、前序哈希，首环为创世区块
- 「一键校验」逐环比对 `prevHash` 与前一条的 `hash`，不是永远返回通过
- 点任意一环查看完整哈希、批次根哈希、帧数、存储位置等

### 统计分析 `#/stat`

交通状态识别、异常事件检测、交通违法取证、机队运行四组共 8 张图表（ECharts，按需引入）。

## 核心交互：事件筛选联动

```
点击左栏任一条告警事件
  ├─ 左栏② 三个 Tab 一起收窄到该事件关联的无人机
  │    航线规划 → 该无人机的航线（含已飞/未飞航段、里程、航时）
  │    任务执行 → 该任务的状态、类型、进度
  │    数据管理 → 该任务的影像 / 视频 / 取证 / 飞行日志
  ├─ 概览卡 KPI 切换为「作用域口径」（关联无人机、任务进度、本任务航时、本任务里程）
  ├─ 地图只保留关联无人机 + 其航线 + 对应任务区域，其余隐藏
  ├─ 右栏① 事件详情切到该事件
  └─ 右栏② AI 分析切到该事件的识别流水与置信度
```

**两套筛选条件的清空是独立的**：

- 事件 chip 上的 `×` 只清除事件筛选
- 筛选栏的「重置」只清除下拉筛选与关键词

下拉筛选与事件筛选是**叠加**关系（事件收窄作用域，下拉在作用域内再筛）。
若叠加后没有匹配结果，页面会明确提示而不是显示空白。

## 地图实现

| 项 | 方案 |
| --- | --- |
| 底图 | Leaflet + 高德公开栅格瓦片（`webrd0{1-4}.is.autonavi.com`），**无需申请 key** |
| 范围 | 锁定上海市域（120.8~122.2E / 30.6~31.95N），`maxBounds` 硬约束，默认缩放 9.5 |
| 极简化 | 瓦片经 CSS `filter: saturate(.1) brightness(1.07) contrast(.9)` 去色，得到接近灰阶的浅色底图 |
| 行政区 | 本地 `src/assets/geo/shanghai.json`（上海 16 区边界，来自阿里云 DataV）画区界细线与区名标注 |
| 坐标系 | 业务坐标与 GeoJSON 统一为 **GCJ-02**，与高德瓦片同源。已用「黄浦江 = 浦东新区/黄浦区行政界」实测比对确认无偏移 |
| 断网降级 | 瓦片加载失败累计到阈值会出提示，本地行政区边界始终渲染，地图不会白屏 |
| 中心城区标注 | 黄浦/静安/虹口/长宁/普陀/徐汇 6 个小区在 zoom < 11 时隐藏标注，避免挤成一团 |

如果后续换用 WGS-84 的 GeoJSON，把 `src/domain/constants.js` 里的 `GEO_SOURCE_CRS` 改为 `'wgs84'`，
`src/utils/geo.js` 会在加载时自动做 WGS-84 → GCJ-02 转换。

## mock 数据

规模：**30 架无人机**（28 在线，其中 10 架执行任务）· **4 个机队** · **20 条任务 / 20 条航线** · **5 条告警事件** ·
**80 条数据资产** · **5 条取证记录** · **21 条 AI 识别结果** · **9 个任务区域** · **3 个交通航区** ·
**6 个空域**（禁飞区 2 / 限飞区 2 / 电子围栏 1 / 航路走廊 1）· 审批状态分布 **已通过 16 / 待审批 2 / 草稿 1 / 已驳回 1**。

数据链路（`src/mock/tasks.js` 是绑定关系的唯一来源）：

```
event ──→ task ──→ drone
              └──→ route
task ──→ taskData / dataAssets（数据管理）
event ──→ evidence（取证）
event ──→ aiResult（识别结果）
```

航线由「手写 3~4 个真实路口锚点 + Catmull-Rom 插值」生成，锚点集中在 `src/mock/anchors.js`，
全部按 GCJ-02 书写，保证点位落在正确的行政区。

`npm run check:data` 会校验全部外键、航线与任务的一一对应、以及「一架无人机不被多个执行中任务占用」。

## 已知限制

- 全部数据为静态 mock，**不随真实时间变化**；「实时分析中」是演示用的动效，不是真实轮询。
- 时间范围（今日 / 近 7 天 / 近 30 天）只切换概览指标的口径数值，不做时间序列回放。
- 「无人机集群」「空域范围」筛选作用于任务与事件；在线无人机总数（28 架）是全域口径，不随筛选变化。
- 地图底图依赖高德公开瓦片服务，断网时会退化为「仅本地行政区边界」的极简底图。
- 航拍快照为内联 SVG 示意图，不是真实影像。
- **航线增删改、空域增删改、任务审批流转、取证校验结果都只存在内存里，刷新页面即恢复初始值。**
  没有用 localStorage 补持久化——那会造成「看起来存下来了、其实不是」的误导。
- **任务审批只扩展字段，不新增任务。** `TASKS.length === ROUTES.length` 是硬约束，
  新建任务必然要配新航线，会打破外键校验，所以审批页不提供「新建任务」入口。
- 角色权限只作用于**数据资产可见性**与**写操作显隐**，不进入监测总览的筛选管线。
- 取证哈希由前端确定性生成，用于演示「证据链完整性校验」的交互，不是真实加密与上链。
- CSV 导出在前端生成，导出的是元数据（编号、类别、时间、密级等），不含真实文件内容。
