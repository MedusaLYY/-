# 低空交通监测系统 · 功能说明

面向城市低空交通监管的**纯前端演示系统**。围绕「无人机低空飞行管理 → 航线规划 → 任务执行 → 数据管理」
这条业务链，叠加交通状态识别、异常事件检测、交通违法取证三类分析能力。

> 无后端、无数据库、无真实接口。所有数据来自本地 mock，地图底图用高德栅格瓦片（免 key）。

---

## 页面结构

顶栏 7 个导航：监测总览 → 空域管理 → 航线规划 → 任务执行 → 数据管理 → 取证存证 → 统计分析。

| 页面 | 路由 | 定位 |
| --- | --- | --- |
| 监测总览 | `#/monitor` | 三栏作战视图，核心是**按事件筛选无人机** |
| 空域管理 | `#/airspace` | OA 表格，禁飞区 / 限飞区 / 电子围栏 / 航路走廊的增删改 |
| 航线规划 | `#/routes` | OA 表格，航线的增删改、避障返航配置与轨迹预览 |
| 任务执行 | `#/tasks` | OA 表格，全量任务查询、详情追溯与**任务审批流转** |
| 数据管理 | `#/data` | OA 表格，数据资产的回传 / 存储 / 检索 / 导出 / 权限 |
| 取证存证 | `#/evidence` | 哈希链可视化与一键校验 |
| 统计分析 | `#/stat` | 四组八张图表 |

两条主线的分工：**监测总览**是「按事件追查」的视角；**四个表格页**是「按台账管理」的视角。
两者共用同一份 Pinia 数据源，改数据两边同步。

# 一、飞行管理功能

## 1. 空域管理

**在哪** `#/airspace`。左侧 12 列 OA 表格 + 右侧范围预览地图。
监测总览地图上也多了一个「空域围栏」图层开关。

**怎么用**

1. 「新建空域」→ 选类型（禁飞区 / 限飞区 / 电子围栏 / 航路走廊）、管控等级、所属区 →
   选**中心点**（真实路口）+ 半径 + 边数 → 表单里即时预览多边形 → 创建。
2. 「编辑」改中心点或半径后，多边形自动重算。
3. 「删除」二次确认。空域没有被任务引用的概念，都可以删。
4. 按类型 / 管控等级 / 所属区 / 状态 / 关键词筛选；点任意行右侧地图缩放到该空域范围。

**怎么设计的**

- **多边形是「中心点 + 半径 + 边数 + 类型」的派生值，不手写坐标。** 禁飞区 / 限飞区 / 电子围栏
  用不规则多边形（`blobPolygon`），航路走廊用长条形（`rectPolygon`，半径当东西向半宽）。
  生成逻辑放在 `utils/airspace.js`，store 与表单预览**共用同一个函数**——
  分两处实现会导致「预览看到的形状」和「保存后的形状」对不上。
- **空域是管制规则，不是任务产物。** 所以 `mapAirspaces` 全量展示、不随任务筛选变化：
  筛任务不该让禁飞区从地图上消失。这点和任务区域（跟随筛选）恰好相反。
- **配色必须写 hex。** Leaflet 的 SVG 渲染器不解析 CSS 变量，写 `var(--danger)` 会渲染成黑色。
- 四种类型用不同线型区分：禁飞区实线、限飞区虚线、电子围栏点线、航路走廊长虚线。
- 「覆盖无人机」列用**射线法**（`pointInPolygon`）判断执行中的无人机是否落在空域内，不是估算。

**边界** 增删改只存内存，刷新恢复初始 6 条；锚点只能从内置路口选；
不检测空域之间的重叠，也不做「无人机闯入禁飞区」的实时告警。

## 2. 无人机低空飞行管理

**在哪** 监测总览左栏第一卡（低空运行概览）+ 第二卡（标题即「无人机低空飞行管理」）+ 中栏地图。

**怎么用** 看概览卡的「在线无人机 28 架」了解总体；用「所属机队」下拉切浦东 / 虹桥 / 嘉定 / 崇明；
点列表任意一行，右栏两张卡跟着切到该任务。

**怎么设计的**

- **位置是算出来的，不是写出来的。** 每架无人机的坐标由任务进度反推：
  `pointAt(route.path, task.progress / 100)`。这样无人机永远落在自己执行的那条航线上，
  改进度位置自动跟着动，也不用维护第二份坐标。同理 `taskId` 也是反查的。
- **地图只画「正在执行任务」的无人机**，待命和离线的画上去只会让地图变脏。
- 30 架无人机分 4 个机队，28 架在线、`SH-UAV-06` 充电、`SH-UAV-27` 离线——
  这两个是刻意留的异常样本，用来验证状态分支。

**边界** 位置是静态快照不移动；不能派任务或返航；只展示电量与在线状态，没有真实遥测数据。

## 3. 航线规划

**在哪** `#/routes`。左侧 10 列 OA 表格 + 右侧轨迹预览地图。
监测总览左栏第一个 Tab 是只读的筛选视图，本页是可写的管理视图，两者读同一份数据。

**怎么用**

1. 「新建航线」→ 填名称、所属区、道路、高度 → 选**起点 / 途经点（最多 3 个）/ 终点**，
   全部从上海 70+ 个真实路口里挑 → 「自动测算」区实时显示里程时长和轨迹形状 → 创建。
2. 「编辑」回填全部信息（锚点坐标反查成路口名），改完保存。
3. 「删除」二次确认。**被任务占用的航线删不掉**，按钮直接禁用。
4. 点表格任意行，右侧地图自动缩放到该航线并标出锚点。
5. 「绑定任务」列可点击，跳到任务执行页并自动打开该任务详情（反向关联）。

**怎么设计的**

- **路径是插值出来的，不是直线。** 锚点连成折线很难看，用 Catmull-Rom 样条
  `smoothPath(anchors, 9)` 插值成平滑轨迹。锚点数 2/3/4/5 对应轨迹点 10/19/28/37 个。
- **里程和时长都是算出来的。** 里程对轨迹逐段累加球面距离；时长 = 里程 ÷ 巡航速度
  （18 km/h，取自现有航线「里程÷时长」的中间水平）。
  **时长不开放手填**——手填容易出现「10 公里飞 5 分钟」这种组合。
- **改锚点必须重算派生值。** `path` / `distanceKm` 是 `anchors` 的派生值，
  `updateRoute` 里强制调用 `resolveRouteGeometry`，否则地图画的还是旧轨迹。
- **删除保护。** 被任务引用的航线禁止删除，否则 `task.routeId` 会指向不存在的航线，外键链断掉。
- **新建的航线不进总览地图**——总览只画「有任务在执行」的航线，
  否则没派任务的航线会被误显示为在飞。要看新航线用本页右侧预览图。

**边界** 增删改只存内存，**刷新页面恢复初始 20 条**；锚点只能从内置路口选，不支持地图点选；
不检测航线交叉与空域冲突。

## 4. 任务执行

**在哪** `#/tasks`。13 列 OA 表格。

**怎么用** 六个维度任意组合筛选（类型 / 执行状态 / 审批状态 / 机队 / 区 / 关键词）。
进度列是彩色进度条（执行中蓝、已完成绿、待执行灰、已中止红）。
点任意行打开详情弹窗：飞行参数、**执行航线**、覆盖任务区域、采集数据资产清单、任务审批。

**与航线的关联（双向可追溯）**

- 表格的「执行航线」列显示 `航线编号 + 航线名称`，**点一下直接跳到航线规划页并选中该航线**。
- 详情弹窗里有独立的「执行航线」区块：起止点、里程 / 时长、锚点与轨迹点数、
  避障策略（含绕行段数）、返航点、返航模式，右上角「查看航线详情」按钮同样可跳转。
- 反向也通：航线规划页的「绑定任务」列点一下，跳到任务执行页并**自动打开该任务的详情**。
- 实现走的是路由 query（`#/routes?focus=ROUTE-01` / `#/tasks?focus=TASK-01`），
  目标页用 `watch(route.query.focus)` 自动选中，不需要额外状态，刷新和分享链接都能用。

**怎么设计的**

- **里程时长取自任务数据，不是航线。** 航线上是全程里程，任务是飞到一半的。
  直接显示航线里程会出现「进度 44% 但里程 9.5 公里」的矛盾。
  `TASK_DATA` 里按进度折算过，和进度条数值自洽。
- **20 条任务的状态分布是刻意的**：执行中 10 / 待执行 4 / 已完成 4 / 已中止 2。
  四种状态都至少 2 条样本，筛选的每个分支都能验证到。
- 关键词同时匹配编号、名称、道路、区、无人机编号、航线名——实际使用中用户记不住编号，
  往往只记得「那个世纪大道的任务」。

**任务审批（本页的第二个能力）**

- **怎么用**：点任意行打开详情弹窗，底部有「任务审批」区，记录按时间正序列成时间线
  （谁、什么时候、什么动作、什么意见）。操作按钮随状态变化——
  `草稿 / 已驳回 / 已撤回` → 「提交审批」；`待审批` → 「通过」「驳回」「撤回」。
  **通过或驳回必须填审批意见**，没填时按钮是禁用的。
- **怎么设计的**：
  - **审批状态与执行状态正交。** 审批通过**不**把 `pending` 改成 `executing`——
    「准飞许可」和「调度状态」是两回事。一旦联动，KPI、地图、无人机占用校验会全部跟着变。
  - **只扩展字段，绝不新增任务。** `TASKS.length === ROUTES.length` 是硬约束，
    新建任务必然要配新航线，所以这一页不提供「新建任务」入口。
  - 审批记录追加用不可变替换（`tasks.value = tasks.value.map(...)`），与航线 CRUD 同一写法。
  - 20 条任务的初始审批状态是刻意配的：已通过 16（执行中 10 + 已完成 4 + 已中止 2）、
    待审批 2、草稿 1、已驳回 1，四态都有样本。
- **边界**：只存内存，刷新恢复初始状态；没有多级审批、没有代理审批、没有审批时限。

**边界（本页整体）** 任务的**派发与执行状态流转**需要后端调度系统，不做假动作；
审批只改审批状态，不改执行状态。

## 5. 数据管理

**在哪** `#/data`。四张类别汇总卡 + 11 列 OA 表格。

**怎么用**

- **回传**：表格有「回传状态」列（已回传 / 回传中 / 排队中 / 失败），未完成的行下面带进度条。
  详情弹窗里有链路质量、带宽、回传时间、重试次数。
- **存储**：按「存储分层」筛选（热 / 温 / 冷 / 取证存储池）；详情里有保留天数与到期时间。
- **检索**：七个维度任意组合——类别 / 存储位置 / 关联任务 / 回传状态 / 存储分层 / 访问密级 / 关键词。
  关键词会同时匹配资产编号、任务编号、任务名、无人机编号、存储位置和标签。
- **导出**：页头「导出 CSV」导出当前筛选结果，行内「导出」导出单条。
- **权限**：右上角用户区可切换角色，数据按密级过滤，导出按钮随权限启用或禁用。

**怎么设计的**

- **资产是派生的，不是独立造的。** 如果单独造 80 条资产，很容易出现
  「资产说采集了 500 张照片，但任务说只飞了 3 公里」这种矛盾。实际链路是：

  ```
  锚点 → 轨迹 → 里程 → 照片数 → 数据资产
  ```

  任何一环改了，下游自动跟着变。
- **存储位置分两个**：影像/视频/日志存「飞行数据湖」，取证记录存「取证存储池」。
  真实监管系统里违法取证数据要满足证据链要求（不可篡改、单独存证），不能和普通业务数据混存。
- 每条资产体积 = 数量 × 单体积，所以汇总卡的总量和明细加总一定对得上。
- **权限只作用于本页，不进筛选管线。** 过滤发生在 `visibleRows` 里，`filteredTasks` 一行不改——
  否则会出现「同一任务在总览可见、在数据页不可见」的割裂。
- **密级比较用等级值（数字）而不是密级字符串。** `1 <= 'restricted'` 会因 NaN 恒为 false，
  把所有数据都过滤掉——这是实现时踩过的坑。
- **CSV 导出的三个关键点**：① 必须加 UTF-8 BOM，否则 Excel 打开中文是乱码；
  ② 字段含逗号 / 引号 / 换行时要用双引号包裹、内部引号写成两个；
  ③ `URL.revokeObjectURL` 要延迟到 `click()` 之后执行，同步释放会让部分浏览器下载中断。
  文本生成抽成了纯函数 `buildCsv`，就是为了能单独验证转义逻辑。

**边界** 只读，不能上传 / 下载 / 归档 / 删除；导出的是元数据，不含真实文件；
角色权限是前端演示，不做真实鉴权。

# 二、分析功能

## 6. 交通状态识别

**在哪** 监测总览右栏 AI 卡 Tab 1；统计分析页「交通状态识别」分组两张图。

**怎么用** 看「拥堵等级」指标（畅通 / 轻度 / 中度 / 严重）和「识别范围」那一行
（没点事件是「全域巡检」，点了事件变成具体路段）。下方是识别流水：时间、结论、位置、置信度。

**怎么设计的**

- **三类 AI 能力用同一张表**，靠 `category` 字段区分。AI 卡的三个 Tab 只是同一列表按类别过滤，
  不需要三套数据结构。
- **拥堵等级用四级枚举不用数字。** 监管看板需要的是可解释的结论（「中度拥堵」），
  不是原始分数。统计页保留 0-10 的拥堵指数折线，那是给趋势分析用的。
- **置信度是真实重算的**，对当前作用域内所有识别记录取平均。点不同事件圆环数字会变，
  不是动画。（`EVENT-01` 的均值刻意调到 0.92 匹配设计稿。）
- 额外做了第四项指标「运行识别」——统计无人机自身异常（载荷/姿态/链路）。
  这是原需求没写但监管业务必然存在的一项：一个是路上的事，一个是飞机的事。

**边界** 识别结果是**预置流水，不是真跑模型**；「实时分析中」是 CSS 脉冲动画不是轮询。

## 7. 异常事件检测

**在哪** 监测总览左栏第三卡（5 条事件，**点击即筛选**）；AI 卡 Tab 2；统计页「异常事件检测」分组。

**怎么设计的**

- **事件是筛选的入口，不是筛选的结果。** 这是最容易做错的地方：如果事件列表也受
  `activeEventId` 影响，点了一条之后列表只剩那一条，**用户再也切不到别的事件**。
  所以 `filteredEvents` 只受下拉筛选影响，不受 `activeEventId` 影响。
- **选中事件时清空下拉筛选。** 如果用户先按「已完成」筛过，再点一条「执行中」的事件，
  结果会是空列表——用户会以为系统坏了。清掉冲突条件，保证点了事件一定看得到东西。
- **点同一条事件即取消**（切换开关的交互习惯），配合 chip 上的 `×`，两种方式退出筛选态。
- 五条事件覆盖五种类型（异常拥堵 / 疑似违停 / 逆行识别 / 低空入侵 / 任务完成），
  圆点颜色各不相同，等级用标签叠加，不看文字也能扫读。

**边界** 固定 5 条；**不能标记已处理、派单、关闭事件**；无实时推送。

## 8. 交通违法取证

**在哪** 监测总览右栏「事件详情」卡（航拍快照 + 取证状态）；AI 卡 Tab 3；
统计页「交通违法取证」分组；`#/evidence` 取证存证页（哈希链）。

**怎么用** 看快照右上角的「已取证」绿标，看底部「取证状态」一行的编号、置信度、**存证状态**。
点「查看飞行航线」地图会缩放到该任务的航线范围。

**怎么设计的**

- **取证挂在事件上，不是任务上。** 取证针对具体违法行为，一次任务可能产出多条取证，
  一条取证也只对应一个违法事件。
- **存证状态（`chainStatus`）** 是这一块最值得说的设计。真实系统里取证要满足证据链要求——
  拍摄时间、地点、设备、内容都不可篡改且可验证。所以除了「有没有拍到」，
  还要回答「这份证据现在还是不是可信的」。对应到数据管理页，取证类数据也单独存「取证存储池」。
- **航拍快照用内联 SVG 画**，不依赖图片。原因：零资源依赖不会 404、配色直接用设计令牌、
  更重要的是**不误导**——用真实街景照片会让人以为是真实航拍数据。
- 「查看飞行航线」按钮会**先把图层打开再飞过去**，否则用户点了什么都看不到。
  用自增 `nonce` 而不是 `taskId` 做触发信号，因为可能对同一条航线连点两次。

**存证链（`#/evidence`）**

- **怎么用**：页面把每条取证记录画成一「环」，带区块高度、本条哈希、前序哈希，
  首环的前序哈希是「创世区块」。点「一键校验」逐环比对，结果显示在顶部横幅
  （未校验 / 校验中 / 通过 / 失败）。点任意一环看完整哈希、批次根哈希、帧数、存储位置。
- **怎么设计的**：
  - **校验是真的在比对**，不是永远返回通过：逐条检查 `prevHash` 是否等于前一条的 `hash`，
    以及 `blockHeight` 是否严格递增。校验逻辑在 `mock/evidence.js` 的 `verifyEvidenceChain()`，
    页面只负责触发与展示——如果它永远返回 true，这个按钮就只是个装饰。
  - **串链前必须按采集时间升序重排。** `EVENTS` 的时间是按「最新在前」写的（14:23 → 08:16），
    直接按原顺序串链会让区块高度与时间方向相反。
  - 哈希用 FNV-1a 混合 + xorshift 展开（`mock/hash.js`）。**不能写成「边遍历边按块输出」**——
    那样前 8 个字符相同的输入（比如都以 `EVIDENCE-` 开头）会得到完全相同的结果。
    第一版就踩了这个坑，5 条记录的哈希全一样。
  - 校验动作受角色权限控制（只读访客与业务操作员不可校验）。
- **边界**：哈希由前端确定性生成，用于演示「证据链完整性校验」的交互，**不是真实加密与上链**；
  没有多节点共识、没有可信时间戳。

**边界** 快照是示意图不是真实航拍；`chainStatus` 只是展示字段；
没有审核通过 / 驳回操作，不能下载证据包。

# 三、核心交互：事件筛选联动

点左栏任一条告警事件后，全站收窄：

| 位置 | 从 → 到 |
| --- | --- |
| 地图无人机 | 10 架 → **1 架** |
| 地图航线 | 10 条 → **1 条**（地图只画在途航线） |
| 飞行管理 · 航线规划 Tab | 20 条 → **1 条** |
| 飞行管理 · 任务执行 Tab | 20 条 → **1 条** |
| 飞行管理 · 数据管理 Tab | 80 条 → **4 条** |

> **列表口径 vs 地图口径**：三个 Tab 的数字都是「当前筛选条件下的全部记录」，
> 与独立页面（`#/routes` 20 行、`#/tasks` 20 行、`#/data` 80 行）一致。
> 地图另有一套口径——只画「有任务在执行」的航线（默认 10 条），避免 20 条航线糊成一团。
> 两者不同是刻意的：**列表是台账视图，地图是态势视图**。
> 从列表里点中一条不在途的航线时，地图会把它补画出来，不会出现「点得动但看不到」。
>
> **空域围栏图层不受事件筛选影响。** 空域是管制规则不是任务产物，
> 筛任务不该让禁飞区从地图上消失——这与任务区域（跟随筛选）恰好相反。
| 概览 KPI | 「上海市全域 · 今日」→「TASK-0912 · 世纪大道拥堵态势监测」 |
| 右栏事件详情 | 切到该事件，含快照与取证状态 |
| 右栏 AI 卡 | 识别范围切到该路段，置信度重算为 **92%** |

**两套筛选条件的清空互相独立**：chip 上的 `×` 只清事件，筛选栏的「重置」只清下拉。
两者可以叠加使用。

**筛选只有一条管线**（`src/stores/monitor.js` 的 `filteredTasks`）：

```
事件作用域 → 下拉筛选（类型/状态/机队/区）→ 关键词
```

其余所有列表全部由它派生，不允许任何组件另起一套过滤条件，否则各处会不同步。

# 四、数据链路

整站是一条单向外键链，`src/mock/index.js` 是唯一出口：

```
机队 → 无人机 ─┐
              ├─→ 任务 ─┬─→ 任务数据 → 数据资产
航线 ─────────┘   │     ├─→ 任务区域
                  │     └─→ 事件 ─┬─→ 取证记录（哈希链）
                  │              └─→ AI 识别结果
                  └─→ 审批记录（挂在任务上）

空域 ── 独立实体，不挂在任务上（管制规则 ≠ 任务产物）
```

**四个关键设计**：

1. **「无人机 ↔ 航线」的绑定只写在一处**（`src/mock/tasks.js`）。
   无人机的 `taskId` 和位置由 `index.js` 派生，不在两个文件里各写一份。
2. **外键完整性有自检**：`npm run check:data` 覆盖 22 条规则——每条引用是否存在、
   每架无人机是否被多个执行中任务占用、任务数与航线数是否一致、审批状态是否合法、
   返航点是否在上海视野内、哈希链是否逐环相接等。
3. **派生的东西不落库**：航线的轨迹 / 里程 / 绕行段从锚点算出来，
   空域多边形从中心点与半径算出来，数据资产从任务数据推出来。
4. **空域是唯一不挂任务的外键实体**——它是管制规则，与任务无引用关系。
   所以删空域不需要任何保护，删航线却必须先检查是否被任务占用。

**坐标系统一 GCJ-02**（与高德瓦片同源，已用「黄浦江 = 浦东/黄浦行政界」在 zoom 14 下比对确认），
不做转换。换 WGS-84 数据源时改 `constants.js` 的 `GEO_SOURCE_CRS`。

# 五、能做什么 / 不能做什么

## 能做什么

- 按告警事件一键追查：谁在拍、航线在哪、产出什么数据
- **空域管理**：禁飞区 / 限飞区 / 电子围栏 / 航路走廊的增删改，地图上同步成可开关的图层
- **航线规划**：选真实路口生成平滑轨迹，自动算里程时长，配避障策略与返航点，增删改查
- **任务审批**：提交 / 通过 / 驳回 / 撤回四态流转，带审批记录时间线
- 全量任务的六维组合筛选与详情追溯
- **数据管理**：回传状态、存储分层、七维检索、CSV 导出、角色权限
- **取证存证**：哈希链可视化与一键完整性校验
- 三类 AI 能力的识别流水、置信度与统计图表
- 事件筛选与下拉筛选叠加使用

## 不能做什么（汇报前务必知道）

| 项 | 实际情况 |
| --- | --- |
| 数据来源 | 全部来自 `src/mock/`，刷新即恢复初始值 |
| 后端 | 无。没有接口调用，没有数据库 |
| 空域管理 | 支持增删改，但只存内存，刷新丢失 |
| 航线规划 | 支持增删改，但只存内存，刷新丢失 |
| 任务审批 | 支持四态流转，但只存内存；**只改审批状态，不改执行状态** |
| 任务派发 | 不能新建任务、派发、中止。`TASKS.length === ROUTES.length` 是硬约束 |
| 数据管理 | 只读；导出的是元数据 CSV，不含真实文件 |
| 角色权限 | 前端演示，只控制数据可见性与按钮显隐，不做真实鉴权 |
| 取证哈希 | 前端确定性生成，用于演示校验交互，不是真实加密与上链 |
| AI 识别 | 结果是**预置流水**，不是真跑模型推理 |
| 「实时分析中」 | CSS 脉冲动画，不是真实轮询 |
| 航拍快照 | 内联 SVG 绘制，不是真实航拍图 |
| 事件处置 | 不能派单、反馈、关闭 |
| 时间范围 | 只切换 KPI 数字口径，不做时间序列回放 |
| 地图底图 | 高德栅格瓦片免 key 直连；断网降级为本地区界 |

> 被问到「这个 AI 是真跑的吗」，如实回答：识别结果是预置的演示流水。
> 接真实后端时替换 `src/mock/` 这一层即可，前端的数据结构与聚合逻辑不用改——
> `checkDataIntegrity()` 已经把外键契约写清楚了。
