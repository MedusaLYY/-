# 内网部署说明

本项目是**纯前端应用**，构建产物 `dist/` 就是一个完整的静态站点——
**不需要 Node、不需要数据库、不需要后端服务、不需要任何接口联调**。

---

## 一、最快路径：静态托管 `dist/`

### 1. 拿到代码

```bash
# 注意：仓库名是 "-"，直接 clone 会生成一个名为 "-" 的目录，
# 而 `cd -` 在 shell 里是「回到上一个目录」的意思，会撞车。
# 所以显式指定一个正常的目录名：
git clone https://github.com/MedusaLYY/-.git lowalt
cd lowalt
```

若内网完全隔离、连不上 GitHub，就用 U 盘把整个项目目录拷过去（排除 `node_modules/`）。

### 2. 起一个静态服务器

`dist/` 里已经是构建好的产物，任选一种方式：

**Python（最省事，多数机器自带）**

```bash
cd dist
python -m http.server 8080
```

**Nginx**

```nginx
server {
    listen 8080;
    root /path/to/lowalt/dist;
    index index.html;
    # 不需要 try_files 重写规则 —— 路由是 hash 模式，服务端只认 index.html
}
```

**Node（如果有）**

```bash
npx serve dist
```

**Windows 免安装**：把 `dist/` 整个拷到目标机，用任意绿色版 http server 指向它即可。

### 3. 访问

打开 `http://<内网IP>:8080/` 即可。

> 资源用**相对路径**引用（`vite.config.js` 里设了 `base: './'`），
> 所以放在域名根目录或任意子目录（如 `http://host/lowalt/`）都能直接跑，
> 不需要改配置、也不需要重新构建。

## 二、要改代码？用开发模式

内网机器需要 Node 18+：

```bash
npm ci          # 按 package-lock.json 精确还原依赖
npm run dev     # http://localhost:5174
```

内网若不能访问 npm 官方源，先配内网镜像：

```bash
npm config set registry http://<内网镜像地址>/
npm ci
```

Windows 也可以直接双击根目录的 `start.bat`（自动装依赖并打开浏览器）。

---

## 三、网络依赖说明（重要）

**唯一的外部网络依赖是高德栅格瓦片底图。**

- 内网若访问不了 `webrd0{1-4}.is.autonavi.com`，地图会**自动降级**：
  隐藏瓦片，只显示本地行政区边界与区名
  （`src/assets/geo/shanghai.json`，已随仓库提交，不需要联网）。
- 降级时地图上方会出现提示「在线底图暂不可用，已切换为本地行政区边界图」。
- **业务功能不受影响**：航线、空域、无人机、事件、任务区域全部是本地矢量绘制，照常显示。

如果需要真正的离线底图，两条路：

1. 预下载瓦片到内网服务器，改 `src/domain/constants.js` 的 `AMAP_TILE_URL` 指向内网地址，重新 `npm run build`；
2. 或直接接受降级形态（行政区边界图）——对内部演示通常够用。

## 五、改了源码后重新构建

```bash
npm ci
npm run check:data   # 改了 src/mock/ 下的数据必跑，外键断裂会直接报错
npm run build        # 产物在 dist/
```

然后把新的 `dist/` 提交到仓库、或直接覆盖内网服务器上的旧目录。

---

## 六、数据是内存态，刷新即重置

这是纯前端演示系统的固有边界，不是部署问题：

- 航线增删改、空域增删改、任务审批流转、取证校验结果**都只存在浏览器内存里**，
  刷新页面恢复初始数据。
- 没有用 localStorage 做持久化（那会造成「看起来存下来了、其实不是」的误导）。
- 如果需要真实持久化，得接后端——替换 `src/mock/` 这一层即可，
  前端的数据结构与聚合逻辑不用改，`checkDataIntegrity()` 已经把外键契约写清楚了。
